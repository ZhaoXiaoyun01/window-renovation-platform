## 建筑配置

单位 mm；坐标 x 向东、y 向上、z 向南，南立面为前、北为后、西为左、东为右。每层独立 floorId、elevationMm、heightMm、footprint、slab。每墙独立 id、floorId、facade、originMm、rotationY、widthMm、heightMm、thicknessMm、openings、finishZones。洞口在墙面局部二维坐标中配置 x/y/width/height，门窗框和玻璃参数独立。附属女儿墙/阳台/退台板等是有独立 ID 的配置构件，不写在场景组件中。尺寸字段保留 source page、status 和 note。

PDF 8 页为栅格图，无可提取文字，使用 Poppler 渲染逐页视觉核对。页1–4是各层平面，页5–8是南/北/西/东立面。标高为0、3800、7100、10400、13700、14300；一层3800，其余层3300；顶女儿墙600。不同页外轮廓标注10200/10260/10320和12200/12260/12320，不能统一冒称实测。MVP按各层外轮廓和四层退台组织：一层10260×12260、二层10200（前）/10320（后）×12260、三层10320×12320，四层后部深约6700；四层平面/立面退台边界差异待复核。窗宽按清晰标注录入，未完整标注的标高/洞口细节标 pending，非实测确认。效果图说明外观，不能提供真实尺寸。墙厚、框厚、板厚、阳台退入等缺少施工详图的参数为演示假设。

## 排砖算法

1. 校验正数、有限值、砖规格、缝宽及洞口合法范围；在毫米空间运算。
2. 水平/竖直方向交换砖宽高；节距是砖净尺寸加缝宽。墙面局部坐标的起点/偏移或居中起铺决定网格相位；楼层纵向可引用标高保证上下对缝。
3. 对每个原砖矩形与墙面矩形求交，扣除洞口矩形。矩形差分最多产生4个不重叠裁片，连续扣除多个洞口；墙体实体用同样的差分分解形成真正洞口。
4. 每个裁片记录 sourceTileId、row/column、x/y/width/height、uvRect。UV按原砖坐标计算，边角裁砖和洞口裁砖只显示原图对应区域，禁止把整张纹理拉伸进余砖或只调整repeat模拟排砖。
5. 墙角砖在两片墙的实际终边分别裁切、保留接缝间隙，返回边缘裁切原因和窄条提示。MVP不把转角当可弯折的整砖；45度碰角/专用阳角条/洞口侧边回铺、错缝和最优采购套裁留后续；统计含女儿墙和露台栏墙外侧，为表面原砖格及裁片数，不等于采购量。
6. 面積统计扣除洞口并单列缝面积。几何合并为每墙少量网格，CPU排版缓存，按需渲染。超过安全网格上限报错而非近似纹理替代。

## 第一阶段与验收

布局参考用户截图：左侧大型可旋转3D场景，右侧参数配置，底部楼层及立面控制；颜色/纹理样例、图片上传（限图片、限制像素/体积并缩略存储）、真实尺寸输入、方向、缝宽/色、应用范围、保存/恢复/重置、独立门窗预留。WebGL错误边界与无支持提示，不静默空白。

顺序：配置/几何算法与边界测试 → 场景 → 独立状态/面板 → 最小接入 → 构建/类型检查 → 原32项后端回归 → 浏览器检查渲染及交互 → 业务文件/数据哈希复核。检查前不把建模假设当施工尺寸，不把演示排版统计当采购清单。


## 实施结果

实现26片独立外墙面（含7片女儿墙/露台栏墙外侧），独立楼层、楼板、框、玻璃与门对象；结构颜色及门色也在building-config集中配置。当前每墙按局部原点或居中网格起铺，不实现跨楼层/跨墙连续对缝。窗口位置、包络简化等证据状态均保留。

原32项后端测试、新9项排砖测试、模块TypeScript检查与生产构建通过。独立模块在原后台服务中可访问；浏览器最终无错误/警告。数据表逐行内容哈希一致，上传原件及原后端/业务组件/API/CSS均未改变；SQLite字节哈希因原服务启动刷新来源索引变化。浏览器与维护说明、未验证项见README末尾。

参考布局比对：保留左侧大场景、右侧开放材质参数栏、底部楼层/立面切换、绿灰米白配色、线性图标及克制字号。用户参考是室内空间展示，本模块按授权功能改为外立面及真实规格表单，未复制室内营销文字、空间缩略图或家具。当前笔记本视口和390px响应式截图已视觉检查；较矮视口底部控制条已修正。
